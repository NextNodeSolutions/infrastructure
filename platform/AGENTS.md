# Rules for the platform package

The platform package is the Pulumi program of the platform, as a function, and the driver that runs it through the Automation API in the deployment job. The root [AGENTS.md](../AGENTS.md) applies here too; these rules are the ones specific to this package.

- **Everything the program creates stays inside the program function.** The program runs inline in the driver's process, and Pulumi tracks resources only within the function it was given. A resource declared at module level, or in a callback that outlives the function, is lost or fails in ways the output does not explain.
- **A resource is keyed by an entry of the spec, and its logical name never changes.** The spec is what the job read from `nextnode.toml`; it is the only input, and it never reaches the program as a file the project could rewrite. Pulumi identifies a resource by its logical name: renaming one makes Pulumi destroy the resource and create another, which for a domain or a database is an outage.
- **Return the identifiers the Worker needs, and nothing secret.** The driver prints the outputs as JSON and the job logs them, so an output is public by construction. A value the Worker must not know, or that must not appear in a log, stays a stack secret and is handed over another way.
- **The driver owns the backend, the passphrase and the version check.** The state bucket, its credentials derived from the platform token, the secrets provider and the stack selection are set in code, not in files a step would template. The pipeline file pins the Pulumi CLI and the Cloudflare plugin at the versions this package pins for their SDKs: bump the four together. The driver refuses a CLI that does not match the SDK, so a half bump fails at once instead of running a mismatched pair.
- **Write TypeScript that Node runs as is.** The job runs the driver with Node's type stripping, with no build step, so only erasable syntax is allowed: no enums, no parameter properties, no namespaces. The manifest's type check enforces it.
- **Check locally before a pull request, against the canary only.** Run the manifest's type check, then the driver in preview mode with a spec shaped like the job's and the platform project's secrets exported in the environment. The canary's stacks are free to use; a real project's stack is production state.
- **A new provider is a plugin to pin in the pipeline file.** The job installs plugins into a cached Pulumi home, keyed by the versions the pipeline file names. A provider that is only in this manifest is downloaded on every run, or not found when the network blocks it.
